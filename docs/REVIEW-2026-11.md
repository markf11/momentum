# Code & Decision Review — November 2026

Scope: whole repo (backend, scheduler, integrations, web, desktop, mobile). Method: code reading plus **execution** — probe scripts against the real services, a fixed-config jest run, a live boot against userspace Postgres 18 + Redis 7, and builds/tests for every client. No repo files were changed besides adding this one.

## Bottom line

`.kiro/specs/motion-calendar/tasks.md` marks all 14 sections done. In reality, **none of the product's core promises works end to end**:

- The scheduler (the "AI") crashes on every call. Patched, it still silently drops work, ignores the user's timezone, and never stops on large inputs.
- The web UI never calls the backend.
- Calendar connect crashes on Node ≥22. On older Node the "encryption" is effectively plaintext.
- Desktop and mobile don't compile. Mobile isn't a runnable RN project.

What does work: the backend boots in dev mode, auth (register/login/refresh/me) works, task CRUD and projects work, WebSocket auth works, the schema is decent, and there's no SQL injection.

The root cause behind most Criticals is that **`@ts-nocheck` (31 files, 12 of them production) plus a relaxed tsconfig were used to make `tsc` pass.** Removing it surfaces 30 production type errors, and several of them are the runtime crashes listed below.

## Critical findings (all verified)

1. **Solver is never runnable.** `ConstraintSatisfactionSolver.ts:369` uses `EncryptionService` without importing it. The only production caller, `routes/meetingBooking.ts:33`, constructs `ReschedulingTriggerService` with 3 of its 6 constructor args. With those fixed, it still calls `collectConstraints` and `generateAvailableSlots` with the wrong signatures.
2. **Solver correctness.**
   - Non-blocking tasks get one chunk and are then marked done.
   - Any one unplaceable task means nothing is scheduled.
   - `startTime` is reset on every recursive call (`:190`), so the time limit is dead.
   - The dependency topo-sort is discarded by `selectNextTask`.
   - `TaskRepository.mapRowToTask` returns `dependencies: []`, so dependencies are never enforced in production.
3. **Timezones.** Working hours, lunch and day boundaries use the *server's* TZ via `setHours`/`getDay`. `user.timezone` is stored but never read, and `DateUtils` (which handles TZ correctly) is unused. With the server on UTC and a New York user, every task lands between 04:00 and 08:45 local.
4. **Token encryption.** `utils/encryption.ts:13` calls `crypto.createCipher`, which was removed in Node 22; this host runs v26, so every Google/Microsoft connect throws. On older Node: the IV is ignored, there's no auth tag, key derivation is MD5, and the hex key from the current `.env` decodes to 1 byte. The docs claim AES-256-GCM.
5. **Production start path.** Path aliases aren't rewritten in `dist/`, and `tsconfig-paths` is a devDependency.
6. **Web frontend is disconnected.** Contexts are local `useReducer` state starting from `[]`, `QueryClientProvider` is unused, and drag-and-drop only calls `console.log`.
7. **Mobile offline queue loses data.** `OfflineManager.syncAction` only logs, then the item is removed from the queue as if it had synced.

## High findings

- **Priority hierarchy (req 3.1) is broken.** One additive score is clamped to 100: "low + hard deadline in 5 days" scores 61, below "critical, no deadline" at 80. "Medium + soft deadline in 12 h" outranks critical, and five task types tie at 100.
- **Slot generation.** Blockers aren't clipped to the working day, overnight events are missed, slots in the past are returned, and `ScheduleValidationService` compares `HH:MM` strings without dates.
- **Rescheduling queue.** Triggers that arrive mid-solve are dropped. Persistence writes rows full of `undefined`, one transaction per task, with no versioning.
- **Auth.**
  - Refresh tokens are not rotated (`AuthService.ts:142-147` returns only an access token).
  - Revoke-all is a no-op: the ioredis `keyPrefix` is applied twice, and `KEYS` patterns don't get the prefix.
- **OAuth.**
  - No `state` parameter and no PKCE, which allows account-linking CSRF.
  - A shared Google `OAuth2Client` singleton mutated per request lets concurrent requests swap users' credentials.
  - The MSAL `refreshToken` check means Microsoft connect always fails.
- **Sync.**
  - Deletes local events that are absent from a partial, future-only, unpaginated fetch, on every webhook.
  - Sync tokens live in memory only and are combined with parameters Google rejects, and 410 isn't handled.
  - Graph uses a non-delta endpoint. Recurring Outlook series never block availability.
- **Webhooks.** The verification secret is the userId, nothing is persisted, and nothing is ever renewed. Graph's limit is 10,080 min; Google channels must be re-created.
- **Infrastructure.**
  - The migration "transaction" runs across different pool clients, and the rollback script doesn't exist.
  - `@ts-nocheck` covers 12 production files.
- **Clients.**
  - Desktop: dev URL is wrong (5173 vs 3000), the frontend isn't packaged, and the `new-window` guard is dead in Electron 25 (no `setWindowOpenHandler`, no CSP).
  - Mobile: push is local-only and uses `react-native-push-notification`, which was archived in Jan 2025.
- **Dependencies.** 10 high and 1 critical prod vulnerabilities. googleapis 122 (latest 190), msal-node 2 (latest 7), Node 18 (EOL).

Medium and low findings (error envelopes, config validation, unbounded metrics, 32-bit booking codes, unauthenticated `/send-reminders`, schema index gaps, corrupted `describe` lines in `monitoring.test.ts:123` and `security.test.ts:190`, duplicated types across 3 clients) are listed in full in the reviewer outputs. Probe scripts are in `~/.hermes/cache/scratch/aical/`.

## Dev-decision verdicts

| Decision | Verdict | Why |
|---|---|---|
| Backtracking CSP for task placement | **Replace** | Exponential and unbounded, returns the first feasible solution (never optimises), and the greedy baseline beats it on every measured case. Use list scheduling (tier → deadline → chunking, dependency-ready selection). Add bounded local search or CP-SAT only if needed. |
| Additive 0–100 priority score | **Replace** | Use a lexicographic key: tier from task attributes, then deadline, then a tiebreak. |
| `@ts-nocheck` + relaxed tsconfig to get green | **Harmful, revert** | It hid every Critical in the scheduler and integrations. Ban it with `@typescript-eslint/ban-ts-comment`. |
| "Microservices" (README, design.md) | **False, and that's fine** | It's one Express process. A modular monolith is right at this size; fix the docs. |
| Layered controllers/services/repos | Partially sound | No cycles (madge). But "DI" isn't real (services `new` their own deps, plus singletons), which is how the wrong-arity constructor shipped. |
| Express 4 + pg + ioredis + Joi + ws | Fine stack, old runtime | Move to Node 22+, swap `googleapis` for `@googleapis/calendar` (fixes the jest OOM), and patch the vulnerable deps. |
| Hand-rolled single-file migrations | Weak | Adopt node-pg-migrate, Drizzle or Knex with down migrations. |
| In-memory EventEmitter reschedule queue | Prototype-only | Needs rerun-on-dirty and durability. BullMQ fits, since Redis is already present. |
| Wall-clock math in server TZ | **Wrong** | Do day windows in `user.timezone` (Temporal or date-fns-tz) and test under `TZ=UTC` plus a DST week. |
| Token encryption design | **Not implemented as claimed** | Use AES-256-GCM via `createCipheriv`: 12-byte IV, auth tag, 32-byte key validated at startup, key IDs for rotation. |
| Refresh tokens in Redis with TTL | Reasonable, incomplete | Add rotation with reuse detection, store hashed tokens, and use a per-user set or `token_version` for revocation. |
| Webhook secret = userId | **Unsound** | Use a random per-channel secret, persisted and renewed. |
| Docker multi-stage, non-root | Good intent, broken output | The image can't start, has no migrations, and uses Node 18. |
| React + Vite + Tailwind + vitest | Sound | Versions are old. |
| react-query v3 (unused) | Right tool, wrong version | Adopt `@tanstack/react-query` v5 when an API layer exists. |
| react-beautiful-dnd | **Replace** | Deprecated and archived. Use dnd-kit or Pragmatic DnD. |
| Electron thin wrapper | Reasonable, badly executed | Electron 25 is EOL. Packaging, router and IPC validation are all broken. |
| Bare RN CLI mobile | Questionable | The native projects were never generated. Expo would be much less setup. |
| Separate offline queue per client | **Unsound** | Two divergent stubs, one of which loses data. Use one shared sync client against `/api/sync`. |
| Hand-copied domain types ×3 | **Unsound** | Use a shared workspace package or OpenAPI/zod-generated types. |
| `.env` handling | Holds | Gitignored, never committed, and the values are placeholders. |

## Worth keeping

- `migrations/001_initial_schema.sql`: UUID PKs, FKs, CHECKs, `updated_at` triggers. Needs a `002` migration for indexes and constraints.
- Auth basics: bcrypt 12, separate access/refresh secrets, issuer/audience/type checks, 15m/7d expiry.
- Task, project and completion repositories (parameterised SQL) and their routes, apart from the `updateStatus` bug.
- WebSocket auth, plus the overall Express app setup (helmet, CORS, compression).
- The frontend calendar views (Day/Week/Month) as UI components.
- The requirements doc as a product spec.
